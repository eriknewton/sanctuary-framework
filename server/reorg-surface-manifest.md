# Sanctuary Reorg Surface Manifest (Phase 0 keystone)

## What this is

This is the operational registry of every **observable frozen surface** of the Sanctuary MCP server that a future *pure-reorganization* PR (file moves, directory renames, the `l1`-`l4` -> named-layer rename, god-file splits) must **not** change. It is the concrete operationalization of the professionalization plan's generalizing principle. Every reorg PR cites the manifest rows it touches, runs the gates those rows name, and proves the corresponding diffs are empty or path-only.

**The rule (binding, one sentence):** *A pure reorg may change file LOCATION and import PATHS; it must change NO observable product/API/wire/at-rest/display SURFACE.*

If a reorg PR changes any FORBIDDEN-class surface below, it is by definition not a reorg PR.

### The two diff-classes

Because moving a file *necessarily* perturbs some build artifacts, the manifest sorts every surface into exactly one of two classes. A reviewer must neither block expected internal path-churn nor wave through a real behavior change.

- **ALLOWED reorg path-churn** (expected, path-only, must still be reviewed as path-only): package-tarball *internal* file paths under `dist/` (`files: ["dist", ...]` ships the whole built tree, so `dist/operational/*` -> `dist/operational/*` is expected on a layer rename), sourcemap / declaration-map paths, `.d.ts` *re-export specifiers* (the path string inside a `export ... from "..."`, not the exported symbol), stack-trace paths, and coverage-report paths. These change shape but carry no product meaning.
- **FORBIDDEN product/API/wire/at-rest/display change** (default-deny): MCP `tools/list` wire shape, internal tool-registry metadata, operation-policy tiers, the package `exports`/`bin`/`files` *contract* (not the internal tarball paths), build entrypoints, frozen `lN` wire tokens, public TS export symbols, user-visible display/help/generated text, HKDF / crypto domain labels, persisted at-rest namespace/storage keys and the on-disk encoding, served HTTP routes (incl. the did:web route), non-TS runtime assets, the CLI command surface, and the two protected text blocks. Any non-empty, non-path-only diff here halts the PR until classified.

**Tree-grounding note:** every row below was confirmed against the working tree (file paths and tokens grepped). The "75 MCP tools" count is **not** a hardcoded source constant today; it is asserted by the Phase-0 snapshot harness, so it is recorded as "confirm at build time" against the canonical unfiltered registry rather than as a fixed literal here.

## Default-deny diff closing rule

On **every** reorg PR, the following diffs must be **empty or path-only**. The reviewer runs the manifest-selected subset for the surfaces the PR touches; the full set is the catch-all for any surface not individually enumerated above.

1. **Build-artifact diff** (`npm run build`) - path-only under `dist/`; no missing/added entrypoint.
2. **Exported-`.d.ts` diff** - byte-stable except `.d.ts` *re-export specifier* path strings (path-churn).
3. **Package-pack diff** (`npm pack --dry-run`) - `exports`/`bin`/`files`/`main`/`module`/`types` contract unchanged; tarball file-list path-only.
4. **MCP `tools/list` wire snapshot diff** + **internal tool-registry snapshot diff** - both empty.
5. **Operation-policy snapshot diff** (`DEFAULT_POLICY` tiers + generated-YAML parity + unwired-factory list) - empty.
6. **CLI command-matrix snapshot diff** (`TOP_LEVEL_SUBCOMMANDS` + touched-command help/smoke + all 6 bin-name dispatch) - empty.
7. **Asset / route snapshot diff** (`/v1/*`, the did:web route, the `/api/*` routes, dashboard `/v1.1` + port 3501, non-TS assets present) - empty.
8. **Old-fixture decrypt/read diff** (per touched at-rest namespace / HKDF store) - reads byte-identical.
9. **Protected-text-block diff** (8-invariant block, sovereignty-properties block) - empty.
10. **Import-cycle check** (zero-dependency TS-compiler-API / `rg` scanner, no new package dep) - no new cycle.

**Any unexpected product / API / wire / at-rest / display diff DEFAULT-DENIES the PR until it is explicitly classified** - either reclassified as ALLOWED path-churn with a one-line justification in the PR description, or treated as a behavior change that disqualifies the PR from being a reorg. Base gates (`npm run typecheck`, `npm test` with passing count >= the repo-root `.test-baseline`, no vitest transform/collection errors, codex adversarial review, halt-before-merge) run on top of the manifest-selected gates, never instead of them. Where a row's gate column and this list disagree on coverage, **this manifest is authoritative** and the broader gate still applies if the PR touches that surface.
