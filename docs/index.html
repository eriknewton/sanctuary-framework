Local node

One command. Full stack, running locally.

Sanctuary runs on your hardware with your keys. Nothing leaves the machine unless you approve it. Point any MCP-compatible agent at it and the whole sovereignty stack is live.

  • 01

    Client-side keys

    Ed25519 identity generated locally. AES-256-GCM on every write. Keys never leave the box — and never appear in any MCP response, log, or error.

  • 02

    Three-tier approval gate

    Every tool call is classified before it runs. Tier 1 ops require out-of-band human approval. Tier 2 anomalies prompt. Tier 3 auto-allow with encrypted audit.

  • 03

    Local dashboard

    Dark-theme web UI on 127.0.0.1:3501. Real-time SSE, approve/deny buttons, audit viewer. Optional TLS and webhook channels for headless setups.

Architecture

Four layers of sovereignty.

A vertical stack. Each layer isolates a distinct concern — from encrypted memory to portable reputation — so both agents and the humans behind them stay in control.

L1 · persistent memory

Cognitive Sovereignty

Every byte of agent state encrypted at rest with AES-256-GCM. Ed25519 self-custodied identity. Merkle-rooted reads with rollback detection. Memory belongs to the principal.

aes-256-gcm ed25519 argon2id
L2 · operational isolation

Approval Gates

Three-tier principal policy wraps every tool call. Behavioral baseline tracks drift. Context gating controls what flows to remote providers. Encrypted audit log.

approval-gate context-gate audit-log
L3 · cryptographic disclosure

Selective Disclosure

Pedersen commitments on Ristretto255. Schnorr proofs of knowledge. Bit-decomposition range proofs. Prove claims about data without revealing the underlying values.

pedersen schnorr range-proofs
L4 · application

Verifiable Reputation

Signed, sovereignty-weighted attestations. Portable reputation bundles that follow an identity across platforms. Trust bootstrapping via escrow and handshake.

eas-compat portable handshake
Interop

Drop it into any harness.

Sanctuary speaks standard MCP. No forks, no adapters, no special case for your stack. Point your harness at the server and every tool in the sovereignty layer becomes available to your agent immediately.

Claude Code mcp · stdio 
// .mcp.json
"mcpServers": {
  "sanctuary": {
    "command": "npx",
    "args": ["@sanctuary-framework/mcp-server"]
  }
}
OpenClaw mcp · stdio 
# ~/.openclaw/mcp.yaml
servers:
  sanctuary:
    type: stdio
    command: sanctuary-mcp
    args: []
CrewAI python · mcp 
# crewai native mcps field
agent = Agent(
  role="analyst",
  mcps=["sanctuary"],
  tools=[],
)
LangChain python · adapter 
# langchain-mcp-adapters
from langchain_mcp import MCPTool
sanctuary = MCPTool.from_stdio(
  "npx", ["@sanctuary-framework/mcp-server"],
)
60 seconds

From zero to sovereign.

Three commands. A local vault, a self-custodied identity, and a running approval dashboard before your coffee cools.

Step 01 · Install

Boot the server

One npx command. No global install, no build step, no config file required.

$ npx @sanctuary-framework/mcp-server
Step 02 · Connect

Wire into your harness

Add Sanctuary as an MCP server in your harness config. No agent code changes.

$ claude mcp add sanctuary npx @sanctuary-framework/mcp-server
Step 03 · Approve

Open the dashboard

Approve sensitive operations in real time at the local dashboard URL.

$ open http://127.0.0.1:3501
