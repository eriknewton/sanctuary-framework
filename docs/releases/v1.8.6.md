# v1.8.6 (2026-09-08)

v1.8.5 was tagged and built but never published: the fresh acceptance run for it exercised the exact next step that `sanctuary install` prints for a new fortress, with no passphrase supplied, and found that the dashboard boot did not use the custody factor `init` had enrolled. v1.8.6 carries every v1.8.5 change and fixes that, plus two corrections the independent final gate found in the same boot path before the tag.

## What changed

### Fixed

- **The dashboard opens a fortress with the enrolled keyring factor.** The MCP server boot and the dashboard boot resolve their credential through one shared path (explicit passphrase, environment passphrase, environment recovery key, then the enrolled keyring factor and the stored passphrase, each checked against the fortress); a boot never mints a credential, and a refusal names exactly the accepted sources.
- **A fortress created before custody envelopes still opens with its stored passphrase** when a keyring custody item exists that no envelope can verify; the item is reported as present but unverifiable rather than used. The keyring factor a boot receives is cleared from memory across its whole lifetime, including a failed read between resolution and establishment.
- **Default `init` no longer touches the machine-wide Castle Wall trust anchor.** It provisions only the fortress-local vault; the machine-wide anchor is published or migrated only through an explicit, confirmed `castle-wall re-pin`. Every surface that reports wall state (`doctor`, `status`, the dashboard, the MCP health and attestation tools) renders whether a vault has completed that step, and treats an unreadable record as not walled rather than as protected; a record that is absent carries no claim.

## Carried from v1.8.5 (unpublished)

See `docs/releases/v1.8.5.md`: the shared credential resolver for `protect`, `export-passphrase`, the install planner and the server boot; the recovery key staged beside the fortress; the default principal policy; explicit pin adoption or refusal; honest failure cleanup. The capability bounds in the v1.8.4 notes are unchanged.
