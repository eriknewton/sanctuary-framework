# Sanctuary v1.3.3 release notes

**Released:** 2026-05-26

Castle Wall macOS Phase 2.5 retail UX + Track 4A IPC integration + Track 4A.2 sysext socket-path discovery. Five of six Phase 2.5 tracks landed plus the full IPC integration stack: daemon wired into `sanctuary wrap` startup AND a shared discovery file so daemon and sysext find each other.

## What's in this release

### Phase 2.5 retail UX ([#361](https://github.com/eriknewton/sanctuary-framework/pull/361))

- **Track 1 -- AgentDetector.** Swift module that detects OpenClaw, Claude Desktop, Claude Code, Codex CLI, Hermes, Cursor, and Cline on the operator's machine via file, process, and bundle ID scanning. Cline detector ships with a glob match against the actual extension (not the bare `~/.vscode/extensions` directory, which previously false-positived).
- **Track 2 -- Protect UI.** Tabbed agent list in the host app's main window with protect/unprotect controls. Green shield indicates a protected agent. Delegates to `sanctuary wrap --<agent> --no-open` under the hood; the CLI alias `wrap` is preserved for backward compatibility.
- **Track 3 -- First-run UX.** Welcome screen on first host-app launch with batch-protect for detected agents. Sets a UserDefaults flag so subsequent launches go straight to the main UI.
- **Track 4B -- Plain-English activity log.** Event feed in the dashboard polls the server HTTP API every three seconds; events are color-coded and rendered as plain-English sentences (privacy, approval, denial, egress, lifecycle, compliance, integrity).
- **Track 4C -- Vocabulary normalization.** `sanctuary protect` becomes the primary CLI verb (with `sanctuary wrap` preserved as an alias). Dashboard labels switch from `verified` / `wrapped` to `protected`. Help text and three vocabulary-affected tests updated to match.

### Track 4A IPC integration ([#362](https://github.com/eriknewton/sanctuary-framework/pull/362))

- **Daemon wiring.** `startMacOSCastleWallDaemon` wraps `MacOSFlowIpcListener` with policy loader, audit sink, and shutdown registry. Invoked from `sanctuary wrap` startup after fortress bind, before agent harness launch. Daemon lifetime is fortress-scoped; clean shutdown on wrap exit.
- **Best-effort startup.** A daemon startup failure (e.g. Linux EACCES when binding the fortress-scoped socket without root) does not fail wrap. The agent harness still gets wrapped; the IPC daemon will surface its absence at handshake time. Mirrors the existing best-effort discipline for the v1.1 dashboard wiring.
- **Three new CLI verbs:**
  - `sanctuary castle-wall reload` -- reload the policy manifest from disk for the running daemon's fortress.
  - `sanctuary castle-wall audit-dump --fortress <id> --since <duration>` -- emit Castle Wall audit events as newline-delimited JSON.
  - `sanctuary castle-wall approve <request_id> [--scope=once|session|always]` -- operator approval for prompt-disposition flows. Correction, 2026-08-07: on macOS the operator's answer is discarded. A `disposition: prompt` rule is admitted by the signed-manifest gate (its unenforceable set names only `time_window`), the evaluator returns uncertain, and the filter pauses the flow; `resumeFlow` has no call site anywhere in the tree, and the inbound listener logs that the resume path is unbuilt and returns. The CLI still prints "approved (once)" and the server deletes the pending request and audits an `operator_decision`. Linux resolves prompt to a terminal fail-closed drop and is unaffected. Open defect: **IC-01** (`docs/audit/inert-capability-register.md`).
- **Provision-pin auto-bootstrap.** Fresh fortresses now have pinned-pubkey state ready at `sanctuary init`; the existing `sanctuary castle-wall provision-pin` verb stays callable for manual rotation.
- **Second-wrap collision guard.** A second `sanctuary wrap` against the same fortress errors cleanly with a Phase 3 pointer message rather than racing for the UDS socket.

### Track 4A.2 -- sysext socket-path discovery ([#364](https://github.com/eriknewton/sanctuary-framework/pull/364))

Closes the path-agreement gap the 2026-05-25 Track 4A drill identified (Wiki/sessions/sanctuary-castle-wall-mac-phase-2-5-track-4a-ipc-drill-mini1-2026-05-25.md). The daemon binds at `{fortressPath}/castle.sock`; the sysext (separate process, doesn't inherit env from `sanctuary wrap`) previously fell through to a sysext-context home that the user couldn't reach. Track 4A.2 introduces a shared discovery file at `/tmp/sanctuary-castle-active.json`:

- **Daemon side:** writes the file atomically on bind (mode 0644) with `{socket_path, fortress_id, pid, started_at}`. Refuses startup if the file points at a live PID. Removes only its own matching config on shutdown (stale-config-safe).
- **Sysext side:** path resolver checks the discovery file first; only trusts it when the recorded PID is alive. Falls through silently to the existing fallback chain when absent, malformed, or stale.
- **Hardening tradeoff:** `/tmp` is world-writable for first integration. Phase 3 hardens to `/Library/Application Support/Sanctuary/active.json` with admin-write / world-read.

End-to-end IPC validation requires a new sysext bundle build + deploy to operator machines so the sysext-side Swift code becomes active. The npm package ships the daemon-side discovery code immediately.

## What's NOT yet in this release (deferral list)

### Sysext bundle redeploy

Track 4A.2 added Swift code to the sysext. Operationalizing end-to-end requires a fresh sysext build + sign + notarize + install on operator machines (user clicks "Allow" in System Settings during activation). Until that deploys, the path-agreement code is live on the daemon side but dormant on the sysext side.

### Track 4A drill re-firing

The 2026-05-25 drill halted twice at Step 0 (once on missing integration code, once on missing path-agreement). Both root causes are closed by PR #362 + PR #364. The drill spawn prompt (`Review/Coordinator/Castle_Wall_Mac_Phase_2_5_Track_4A_IPC_Drill_Spawn_Prompt_2026-05-25.md`) re-fires unmodified once the new sysext bundle deploys; the 7-rung ladder is still sound.

A small spawn-prompt clarification still pending: how to express the drill subject (a curl loop that exercises NEFilterDataProvider scope). Minor scope item; does not block the integration claim. To be addressed before re-firing.

### Dashboard republish

Phase 2.5 deployed dashboard changes to Mini1 via in-place `dist/` swap. This release includes those changes via npm publish so downstream `npm install -g` consumers receive the `protected` vocabulary and the new CLI verbs.
