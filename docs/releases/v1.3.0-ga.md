## The Castle Architecture, in plain English

Sanctuary's Castle Architecture has four layers. Each layer does one job. The layers compose, but they do not substitute for each other.

**Castle Wall, Castle Layer 1.** The Castle Wall is operating-system-level egress filtering at the boundary between the operator's machine and the external world. It is kernel-level enforcement. Even a prompt-injected agent cannot bypass it within the proven macOS scope, because the agent does not get to decide whether unauthorized traffic reaches the network. The operating system rejects unauthorized cross-boundary calls. Linux Phase 1 shipped on May 7, 2026. macOS Phase 1 shipped on May 13, 2026. This layer is real enforcement, not advisory policy. (Correction, 2026-08-07: that description holds on macOS within the proven scope: one host, one OS version, signed extension installed and armed, attended reboot proof only. The shipped Linux daemon installs no kernel enforcement. Open defect: **IC-02, IC-03, IC-04**.)

**Sentinels, Castle Layer 2.** Sentinels observe what happens inside the boundary. They use audit-log statistical detectors to surface anomalies to the operator through the unified inbox. They do not enforce. They are pure observation. The shipped detector set covers per-agent activity, CUSUM, PSI, cross-agent timing, tool-call sequence, and audit-event-class distribution.

**Cooperative MCP, Castle Layer 3.** Cooperative MCP is the additive sovereignty surface for agents that honor the operator's policy. It includes approval gates, English-authored policy gates, honeypot authoring, the auto-trigger ladder, and the unified inbox with operator-facing operations. This is the path for compliant agents to work well inside the castle.

**Cryptographic receipts and reputation, Castle Layer 4.** Layer 4 is post-action accountability across castles. Concordia receipts and Verascore reputation compose so operators can carry signed evidence, reputation, and cross-castle accountability outside a single vendor relationship.

## Why this matters

Sanctuary's substrate position is operator-level sovereignty that is enforceable, not advisory.

The Castle Wall is the core enforcement piece. If an agent gets prompt-injected and tries to exfiltrate operator data, the operator does not have to trust that agent to remember the rules. The kernel rejects unauthorized cross-boundary calls before they escape the machine within the proven macOS scope.

Cooperative MCP matters for a different reason. It is the sovereignty surface for agents that do honor policy: approvals, policy gates, honeypots, unified inbox routing, receipts, and operator control in the normal flow of work. That layer should be easy to use. It should feel like the right path.

v1.3 ships both: hard enforcement at the boundary plus a usable cooperative surface inside it.
